# match-tabular-records

通用表格记录匹配 skill，用于按一个字段或一组字段核对两份 CSV/XLSX 数据，输出精确匹配、双向不匹配、覆盖率、包含关系和审计结果。

## 适用场景

- 按稿件 ID、作品 ID、订单号、账号 ID 等唯一标识核对两份数据。
- 按“标题 + 作者”“姓名 + 手机号”等复合字段匹配。
- 检查一个文件是否为另一个文件的子集。
- 统计匹配率、缺失记录、重复主键和无效主键。
- 对主键未匹配的数据，用标题、作者等字段做补充判断。
- 连续多轮增量匹配：先剔除历史已匹配 ID，再匹配本轮新增数据。
- 合并审稿、投稿、采集、结算等不同链路导出的表格。
- 在匹配结果中扩展业务字段，例如“最终审核结果”。

## 不适用场景

- 只凭语义相似度或内容理解进行模糊匹配。
- 未明确字段对应关系时直接猜测主键。
- 自动修改、删除或覆盖原始数据。
- 将标题或作者的补充匹配直接计入主键 inner join。

## 支持的匹配方式

| 方式 | 示例 | 推荐标准化 |
|---|---|---|
| 单字段 | `稿件ID = 作品ID` | `id` |
| 复合字段 | `标题 + 作者` | `text + text` |
| 数值字段 | `订单金额 = 结算金额` | `number` |
| 日期字段 | `发布日期 = 入库日期` | `date` |
| 时间字段 | `创建时间 = 提交时间` | `datetime` |
| 完全一致 | 保留原始大小写和空格比较 | `exact` |

标识符匹配会统一 Unicode 宽度、大小写、空白、前导单引号、整数小数形式和科学计数法，避免格式差异导致同一 ID 被识别为不同记录。

## 输入要求

- 两份 `.csv` 或 `.xlsx` 文件。
- 明确两端对应的主键字段。
- 复合匹配时，字段顺序必须一一对应。
- 可选：次级匹配字段、日期字段、工作表名称和表头行号。

原始文件只读，不会被修改。

## 标准输出

默认生成一个 Excel 工作簿，包含四个可见 sheet：

1. `匹配表_inner join`
2. `不匹配详情_文件A`
3. `不匹配详情_文件B`
4. `分析汇总`

实际项目可将“文件A/文件B”替换为业务链路名称，例如“审稿后台”“全量投稿笔记”。

分析汇总包含：

- 两端记录数、有效主键数和唯一主键数
- inner join 行数和唯一匹配主键数
- 两端匹配率与方向性不匹配数量
- 重复主键、无效主键和长数字精度风险
- 标准化前后交集变化
- 子集/包含关系
- 次级字段补充匹配数量

## 典型请求

```text
根据稿件ID匹配这两个文件，输出匹配表、两张不匹配详情表和分析汇总。
```

```text
按标题和作者两个字段做复合匹配，统一空格和大小写。
```

```text
先排除上一轮已经匹配的稿件ID，再对本轮两个全量文件做增量匹配。
```

```text
主键按作品ID匹配；未匹配数据再用标题和作者判断，但不要计入inner join。
```

## 命令行示例

```powershell
python scripts/match_tabular_records.py `
  "C:\path\审稿后台.csv" `
  "C:\path\全量投稿.xlsx" `
  --left-key "稿件ID" `
  --right-key "作品ID" `
  --key-normalizer id `
  --left-label "审稿后台链路" `
  --right-label "全量投稿链路" `
  --output "C:\path\字段匹配结果.xlsx"
```

使用标题和作者做补充判断：

```powershell
python scripts/match_tabular_records.py `
  "C:\path\审稿后台.csv" `
  "C:\path\全量投稿.xlsx" `
  --left-key "稿件ID" `
  --right-key "作品ID" `
  --key-normalizer id `
  --left-secondary-key "内容标题" `
  --right-secondary-key "笔记标题" `
  --left-secondary-key "作者昵称" `
  --right-secondary-key "作者昵称" `
  --secondary-normalizer text `
  --secondary-normalizer text `
  --output "C:\path\字段匹配结果.xlsx"
```

## 增量匹配流程

1. 从历史结果的 `匹配表_inner join` 提取唯一主键。
2. 验证各轮历史主键之间是否重叠。
3. 从本轮两份源数据中同步剔除累计历史主键。
4. 对剩余数据执行本轮精确匹配。
5. 验证历史主键未出现在本轮匹配表和两张不匹配表中。
6. 在分析汇总中记录各轮历史数量、累计剔除量和本轮结果。

## 业务字段扩展

匹配结束后可以按项目规则增加派生字段。例如审稿场景中的“最终审核结果”：

```text
人工复核结果非空时覆盖 Agent 审核结果；
人工复核结果为空时采用 Agent 审核结果。
```

此类派生字段应使用 Excel 公式，并在分析汇总中写明口径和覆盖数量。

## 验证标准

交付前至少验证：

- 主键集合、inner join 和双向差异集合完全一致。
- 主键按文本保存，无科学计数法和精度损失。
- 重复键、空键和无效键数量准确。
- 次级匹配不改变主键精确匹配口径。
- 工作簿 sheet 顺序、行列数和 OOXML 完整性正确。
- 无 `#REF!`、`#VALUE!`、`#DIV/0!` 等公式错误。
- 所有 sheet 均完成可视化检查。
