# LG 27UP850 + RTX 3060：控制器局部重置恢复音频

日期：2026-10-26（Asia/Singapore）。这是一次现场验证，不能推广成所有待机无声问题的根因。

## 故障与环境

- Windows 11 家庭版，系统版本 10.0.26200；RTX 3060，图形驱动 32.0.16.1088，NVIDIA High Definition Audio 1.4.5.7。
- HDMI 连接 LG 27UP850，使用显示器内置扬声器。全系统无声，显示器重启无效，以往电脑重启后恢复。
- 用户观察到长时间待机后出现，短时间未复现；没有测出精确时间门槛。
- 显示器 Automatic Standby 原本 Off；Deep Sleep Mode 原本 On，排查中改为 Off。

## 故障现场证据

Console、Multimedia、Communications 默认输出均为 LG ULTRAFINE，音量非零、未静音。Windows Audio、AudioEndpointBuilder 和 PnP 状态正常。存在 ToDesk 虚拟声卡，但不是默认输出。

双声道输出为 16 位 48 kHz，未启用具体增强效果。两声低振幅合成测试音的 Core Audio 峰值非零，用户确认完全听不到；共享流播放时钟 50/50 次采样推进，无调用错误。峰值与时钟只证明引擎内存在/处理信号，不证明声压输出。

事件日志记录 LG/NVIDIA 端点断开后重新可用。驱动 PowerSettings 的空闲时间为 4，IdlePowerState 为 3（D3）；该配置没有被更改，也没有证明它造成了本次故障。4 秒空闲参数不能直接解释用户描述的数小时条件。

## 实际对照结果

| 操作 | 系统结果 | 听感/结论 |
| --- | --- | --- |
| 重启 Windows Audio 并恢复原运行依赖服务 | 成功，音频引擎进程更换 | 测试仍完全无声。 |
| 直接重启 NVIDIA HDAUDIO 子设备 | 返回 3010；Kernel-PnP 225 指出 audiodg.exe 句柄占用 | 未完成即时设备重启，不能算有效重启后的失败试验。 |
| 停止 Windows Audio 释放占用后再重启同一子设备 | 返回 50，设备等待前一次操作所需的系统重启 | 未绕过/清除标记；恢复相关服务。 |
| Deep Sleep Mode 改为 Off | 用户完成菜单变更 | 当前故障未立即解除；长期防复发效果未知。 |
| 拔下电脑端 HDMI，约 5 秒后插回 | 图像和端点恢复 | 测试仍完全无声。 |
| 停止 Windows Audio，重启 NVIDIA 独立 PCI 音频控制器，再恢复服务 | PnPUtil 返回 0，明确成功 | 用户确认“现在有声音了”。电脑没有重启。 |

中途尝试在声音属性里切换格式，但没有真正应用；读回仍为 16 位 48 kHz。这不是已完成的格式对照试验，也不是恢复原因。

## 有效操作的边界

由 NVIDIA HDAUDIO 子设备的 `DEVPKEY_Device_Parent` 找到直接父控制器，核实 Class=System、Service=HDAudBus、PCI 厂商为 NVIDIA。现场该控制器为独立音频 PCI 功能，与 Class=Display 的图形设备分开。父控制器没有待重启标记。

保存运行中的依赖服务 -> 停止 Audiosrv -> 等待 audiodg 退出 -> 只重启已核实的 PCI 音频控制器 -> finally 恢复 Audiosrv 与原运行依赖服务 -> 重复相同测试音并由人确认。

收尾时控制器及 HDAUDIO 子设备均为 OK、ProblemCode=0、IsRebootRequired=false；Audiosrv、AudioEndpointBuilder、RtkAudioUniversalService 均 Running/Automatic；输出仍为双声道 16 位 48 kHz。没有卸载驱动、改注册表、重置图像显卡或重启整机。

## 已知与未知

- 已验证：本次可通过局部音频控制器重置恢复，无需重启整机。
- 证据指向 NVIDIA HDMI 音频链路的运行状态恢复异常；具体驱动 bug、固件机制或电源转换尚未锁定。
- audiodg 占用解释的是设备重启受阻，不是初始失声根因。
- 未证实物理硬件损坏；未做相同长待机或隔夜防复发试验；不宣称“根治”。
