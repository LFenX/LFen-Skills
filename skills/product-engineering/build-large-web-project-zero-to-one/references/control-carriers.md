# 需求与验收的留痕载体

复杂 Web 项目不能只靠聊天记录或本地代码注释管理。需求方需要能共同查看、补充和确认，因此默认使用飞书云文档/多维表格；没有 `lark-cli` 或无法访问飞书时，用 Excel 兜底，并保持相同的编号和字段口径。

## 载体选择

| 内容 | 首选载体 | 说明 |
|---|---|---|
| 需求文档 | 飞书云文档（Docx/Wiki） | 需求方可共同编辑、评论和确认；保留原始需求及修订历史 |
| PRD、产品包索引、会议纪要 | 飞书云文档 | 适合连续文字、图片、流程图和链接 |
| 需求变更、开发进度、验收问题、BUG | 飞书多维表格（Base） | 一行一个事项，可筛选、分组、分配、更新状态 |
| 页面效果图、截图、附件 | 云文档附件或 Base 附件字段 | 通过稳定链接关联需求或问题编号 |
| Excel 兜底 | 本地 `.xlsx` | `lark-cli` 不可用或无权限时使用；不伪装成已同步到飞书 |

叙述性内容和可逐条跟踪的事项可以同时存在，但不要在两个地方维护同一事实的不同版本。需求文档是需求内容的权威来源；Base 或 Excel 是事项状态和验收过程的权威来源。

## 飞书优先流程

1. 检查 `lark-cli` 是否可用，以及当前用户是否有目标文档/Base 的访问权限。
2. 有权限时，建立或复用需求云文档，并把需求方原始内容、讨论结论和修订记录写入文档。
3. 建立或复用 Base 记录需求变更、开发进度、原型验收和联合验收问题。
4. 在产品包索引中互相链接云文档和 Base；每条记录使用稳定的需求 ID、问题 ID或任务 ID。
5. 每次会议、基线变更、验收和返修后更新对应载体，不等到项目结束再补录。

需要实际操作飞书时，按目标资源切换到 `lark-doc`、`lark-base` 或相关 Lark Skill；本 Skill 不假定某个固定 Base token、字段 ID 或组织权限。

## Base 控制表的最小结构

建议至少有一张“反馈/验收记录”表，一行对应一条可跟踪事项。最小字段为：

- 问题 ID或自动序号
- 提出人
- 问题描述
- 阶段标签：可记录原型不符合、待讨论事项等发现阶段
- 闭环分类：缺陷、需求遗漏、新增优化、后续事项（统一枚举）
- 重要度：P0 阻断、P1 严重、P2 体验向（可按项目调整）
- 开发状态：待开发、开发中、已完成
- 验收状态：未验收、验收不通过、验收通过
- 回复或处理结果
- 截图/附件
- 关联需求 ID或任务 ID

若沿用已有 Base 的“问题类型”字段，保留 `BUG/需求/建议` 作为兼容字段，并按以下规则填写统一的“闭环分类”：`BUG` → 缺陷；`需求` → 需求遗漏或新增优化；`建议` → 新增优化或后续事项。最终类别由是否属于原需求范围及本版本是否处理决定，不能只依赖旧字段名称。

按需增加：

- 开发进度：澄清需求、规划中、执行中、复核中、返修中、已完成
- 生产部署状态
- 规划、执行、复核、返修、完成时间
- 自动计算的各阶段耗时
- 值守开发者或模型

可建立以下共享视图：汇总、BUG、产品需求、最高优先级、待开发、开发完成、尚未验收、验收通过、未通过验收、已部署。视图只是派生展示，不改变记录本身。

用户提供的 [反馈记录 Base](https://funplus.feishu.cn/base/MfgRbZHPkaTgrRsOBTRc4xKannc?from=from_copylink) 已采用这类结构：包含问题类型、重要度、开发状态、验收状态、生产部署、时间字段、回复、截图和多个按状态/类型划分的视图，并使用自动化记录时间。它是可借鉴的实例，不是必须照搬的固定 Schema。

## 没有 lark-cli 时的 Excel 兜底

在项目目录之外创建一个 `.xlsx` 控制工作簿，建议使用以下工作表：

### Requirements

| 需求 ID | 原始需求 | 来源 | 当前最终表述 | 状态 | 修订原因 | 影响文档/任务 | 决定记录 |
|---|---|---|---|---|---|---|---|

### Meeting Log

| 会议 ID | 日期 | 参与者 | 已对齐结论 | 冲突/待定项 | 下一步 |
|---|---|---|---|---|---|

### Package Index

| 产物 | 文件路径/链接 | 版本 | 最后更新 | 说明 |
|---|---|---|---|---|

### Execution Plan

| 任务 ID | 层次 | 子任务 | 前置任务 | 关联需求/控件 | API/数据/权限 | 验收场景 | 状态 |
|---|---|---|---|---|---|---|---|
| FE-001 / BE-001 | 前端/后端 | {{可独立验收的子任务}} | {{任务 ID}} | R-xxx / C-xxx | {{接口、字段、角色范围}} | S-xxx | 待开始 |

### Component Binding

| 控件 ID | 页面/组件 | 需求 ID | 角色/权限键 | 入口 | 出口 | 数据/API/状态 | 加载/空/失败/无权限 | 前端任务 | 后端任务 | 验收场景 |
| C-001 | {{页面/按钮/行操作}} | R-xxx | {{角色、权限键、数据范围}} |  |  |  |  | FE-xxx | BE-xxx | S-xxx |

控件绑定表一控件一行、`C-xxx` 唯一；G3/G4 前逐页核对所有按钮、图标、行操作和菜单项，覆盖率必须为 100%。

### Acceptance Issues

| 问题 ID | 阶段 | 阶段标签 | 闭环分类 | 重要度 | 描述 | 期望/实际 | 证据 | 开发状态 | 验收状态 | 处理结果 | 需求方结论 |
|---|---|---|---|---|---|---|---|---|---|---|---|

### Retrospective

| 经验 ID | 场景 | 问题 | 根因 | 项目修正 | 是否通用 | Skill 改进候选 |
|---|---|---|---|---|---|---|

Excel 兜底要求：

- 维持与飞书版本相同的 ID、状态和分类名称。
- 不把截图、需求原话或反馈内容只放在聊天里；用单元格文本、超链接或附件路径保存。
- 每次修改记录日期和修改人。
- 若之后恢复飞书能力，按 ID 合并或导入，不要重新生成一套不同编号。
- 本地文件只表示当前项目的真实留痕，不声称已经与飞书同步。

## 降级和恢复

- `lark-cli` 未安装：直接使用 Excel/本地 Markdown，不因工具缺失阻塞需求整理或验收。
- 已安装但未登录或权限不足：提示用户授权；用户暂不授权时使用 Excel 兜底。
- 飞书写入失败：保留失败信息和本地记录，修复权限或连接后再同步；不要静默丢弃记录。
- 飞书与 Excel 同时存在时，先确定哪一个是当前权威来源，再同步另一份，禁止两边无规则覆盖。
