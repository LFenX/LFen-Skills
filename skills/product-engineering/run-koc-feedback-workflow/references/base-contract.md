“开发状态”需要保留或补充以下选项：

“值守大模型”和“生产部署”不属于 Agent 可写字段。任何认领、阶段同步、完成、返修或发布相关操作都不得在写入补丁中包含这两个字段；Agent 只能读取并向用户展示现值。“值守大模型”由人工维护；“生产部署”仅允许用户本人手工新增、修改或清空。

首次使用发现“唤起开发时间”、“开发状态”、“开发进度”或任一必需选项（包括“开发状态”的 `已完成`）缺失时，列出准确差异并请求结构变更授权。未获授权前可以列举和只读探查，不能假装已登记缺失字段。

## 候选查询

候选集合只排除“唤起开发者”的值恰好为 `{LFen}` 的记录。

推荐做法：

1. 读取“唤起开发者”的真实选项。
2. 服务端查询空值记录。
3. 对每个非 `LFen` 选项做 `intersects` 服务端查询。
4. 按 record_id 去重；这样会保留 `{LFen, Agent}`，同时排除 `{LFen}`。
5. 用户指定问题类型或其他条件时，将相同条件加入每个查询。
6. 串行处理分页，直到每个查询 `has_more=false`。

若 Base 筛选能力无法表达组合条件，允许在完整且不超过 200 行的结果上做集合判定；超过 200 行时不得用默认页或局部结果形成“全部”结论。

## 列举输出

按“序号”升序，展示用户可读字段，不展示内部 record_id、file_token 或 open_id。截图列只写“有（N 个）/无”；用户要求时再展示或分析附件。

## 写入协议

1. 写入前用序号定位真实 record_id，并逐条 `record-get` 回读当前“开发状态”“开发进度”“唤起开发者”“回复”和目标字段。
2. 任一记录不再符合授权范围或候选规则时，整批停止；不要部分认领。
3. 认领逻辑补丁必须是：
   - 开发状态：`开发中`
   - 唤起开发者：精确集合 `[LFen, Agent]`
   - 唤起开发时间：Asia/Shanghai 的 `YYYY-MM-DD HH:mm:ss`
4. 使用 `lark-base` 的真实字段结构和记录写入 reference 构造 CellValue；不要猜 JSON 形状。
5. 同一批记录使用同一认领时间。连续写同一表时串行；按 `lark-base` 规则处理并发冲突。
6. 每次写后回读目标字段。只有开发状态、唤起开发者和唤起开发时间与期望一致，才推进下一阶段。

认领回读通过后，将“开发进度”写为 `澄清需求` 并登记“澄清需求时间”。中间阶段只更新“开发进度”和对应阶段时间，“开发状态”保持 `开发中`。进入完成终态时，在同一次记录更新中将“开发进度”和“开发状态”均写为 `已完成` 并登记完成阶段时间；随后回读两字段，只有两者均为 `已完成` 才视为同步成功。

## 澄清结果登记

默认追加到“回复”，不得覆盖已有回复。格式：

```text
[需求澄清 YYYY-MM-DD HH:mm:ss]
结论：<达成共识的问题定义>
范围：<本次会做与不做>
验收：<可观察的验收标准>
证据：<代码、截图、测试或文档依据>
未决：无 | <仍需决定的事项>
```

如果用户指定专用澄清字段，则改用该真实字段；字段不存在时先请求结构变更授权。
